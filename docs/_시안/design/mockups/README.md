**참고 자료(앱에 쓰지 않음)**: `design/v2_design_samples_html.zip`(제미나이 샘플 3종), `docs/v2_sample_2_light.html`(샘플2 라이트판). 외부 CDN(Tailwind·Google Fonts)을 써서 사내망에서는 깨져 보일 수 있다. 비교 분석은 `docs/08_벤치마킹_샘플2.md`.

## B안 (2026-10-23) — 덜어내기 · 매끄러운 진행 · PC·빔프로젝터 시인성

**스타일(같은 날 개정)**: iPadOS 27 그룹 목록 — 테두리 없이 회색 바탕 위 흰 카드(모서리 12), 카드 안 얇은 구분선, 큰 제목(28), 왼쪽 사이드바, 세그먼트·채움 버튼. 밀도는 조밀(본문 15 · 행 40 · 버튼 36, 최소 글자 13). Liquid Glass 반투명은 쓰지 않는다. Apple UI 키트는 라이선스상 Apple 기기용 앱에만 쓰므로 원칙만 따르고 컴포넌트·SF 글꼴은 가져오지 않는다(글꼴은 앱 로컬 Meeting Sans KR). 참고: Figma Community 「iOS and iPadOS 27」 · 「macOS 27」(Apple).

A안을 고치지 않고 따로 둔다. 머리줄 오른쪽 「A안 보기」로 같은 화면의 A안을 연다. 공통 파일은 `v2b.css`(토큰 포함, 글자 13·15·17·22·30, 2px 선, 진한 유형 라벨), `v2b.js`(되돌리기 알림·슬라이드 축소·단축키), `v2b-data.js`(모든 B안 화면이 같은 가상 이슈·회의).

## C안 (2026-10-23) — 회의자료 스튜디오 `v2c-studio.html`

B안 「회의자료 편집」을 Figma 편집기 구성으로 바꿔 본 안. 참고: Figma Community 「Website Wireframes UI Kit」(섹션 변형을 어두운 캔버스에 나란히 두고 고르는 방식).

- 위 도구줄(회의 이름·갈래·확대·발표 미리보기·발행) · 왼쪽 「장」(레이어, 끌어서 순서)/「후보」 · 가운데 **어두운 캔버스**(장 = 프레임, 고른 장 옆에 다른 형태 변형이 흐리게 — 누르면 그 형태로) · 오른쪽 **속성**(형태 4종 썸네일, 회의용 한 줄·머리표, ● 사실 = 이슈에 반영).
- 단축키: ↑/↓ 장 고르기, 1~4 형태, Delete 빼기(되돌리기), 확대 −/＋/맞춤.
- 패널은 B안(iPadOS 그룹 목록·조밀) 그대로, 캔버스만 어둡게. 반투명 없음. 슬라이드는 1920×1080 기준 본문 26px 이상.

## (이전) 최종 시안 B안 + C안 — v2s 로 대체됨

구현은 이 묶음을 따른다. 스타일은 B안(iPadOS 그룹 목록 · 조밀 · 테두리 없음), 회의자료 만들기는 C안 스튜디오에 B안 흐름을 합친 `v2b-studio.html`.

| 파일 | 화면 |
|---|---|
| `v2b-home.html` | 홈 — 남은 일 대기열(Enter 로 다음 칸), 역할 3개 |
| `v2b-issue-desk.html` | 이슈 — 원장 + 위에서 아래로 한 흐름, 자동 저장, 초안 완료 → 다음 초안 |
| `v2b-import.html` | 가져오기 — 메모·메일·PPT 입구 하나, 조각 판정 → 다음 조각 |
| `v2b-meetings.html` | 회의 목록 — 행 = 그 회의의 다음 할 일 |
| **`v2b-studio.html?kind=dept·share·exec`** | **회의자료 스튜디오** — 왼쪽 장(끌어서 순서·Shift+클릭 여러 장)/후보 · 가운데 어두운 캔버스(장 = 프레임, 고른 장 옆에 다른 형태 변형) · 오른쪽 속성(형태·회의용 한 줄·머리표·● 사실). B안 흐름: 부서 자료는 「지난주 이어받기 / 빈 자료」로 시작, 공유회는 늦은 부서 「원장으로 채우기」, 여러 장 → 「한 장으로 요약」(풀기 가능), 제출·발행 → 다음 단계 버튼, 모두 되돌리기. 단축키 ↑↓·1~4·Delete·Ctrl+S |
| `v2b-meeting-view.html` | 회의자료 보기 — 읽기 전용, 「편집」 → 스튜디오 |
| `v2b-meeting-run.html` · `&view=present` | 회의 진행 · 발표 — 안건마다 「기록하고 다음」 |

공통: `v2b.css` · `v2b.js` · `v2b-data.js`. 대체된 시안(비교용으로만 남김): `v2b-deck-edit.html`(B안 회의자료 편집) · `v2c-studio.html`(C안 스튜디오 원형) · `v2-*.html`(A안).

## (이전) 전체 스튜디오 틀 `v2s-*` — v2m 으로 대체됨

구현은 이 묶음을 따른다. 모든 화면이 같은 틀: **위 도구줄**(메뉴 탭 · 제목 · 동작) · **왼쪽 목록** · **가운데 어두운 캔버스**(작업 대상 = 프레임) · **오른쪽 속성·동작**. 패널은 B안(그룹 목록·조밀·테두리 없음), 캔버스만 어둡게, 반투명 없음. 공통: `v2b.css`(토큰) + `v2s.css`(셸) · `v2b.js` · `v2b-data.js` · `v2s.js`(도구줄·장 형태·프레임).

| 파일 | 왼쪽 | 캔버스 | 오른쪽 |
|---|---|---|---|
| `v2s-home.html` 홈 | 역할 + 남은 일 | 고른 일의 대상(1차 초안 / 부서 자료 장 / 사례 카드) | 그 일의 동작(한 줄 Enter → 다음 일) + 다가오는 회의·부서 제출 |
| `v2s-issue.html` 이슈 | 원장(칩·찾기·체크 → 일괄) | 1차 초안 크게 + 다른 형태 + 붙인 것 | 기본·내용·매핑(자동 저장, 캔버스 즉시 반영) — 「초안 완료 → 다음 초안」 |
| `v2s-meetings.html` 회의 | 이번 주·지난 회의 | 그 회의의 장 전부(읽기 전용, 발행 뒤 바뀐 장 주황) | 회의 정보·부서 제출 — 「스튜디오에서 편집」·「회의 시작」 (**회의자료 보기 화면을 합침**) |
| `v2s-studio.html?kind=` 회의자료 스튜디오 | 장/후보 | 장 프레임 + 형태 변형 | 형태·한 줄·머리표·● 사실 — 이어받기·원장으로 채우기·요약·제출/발행 |
| `v2s-run.html?m=` · `&view=present` 회의 진행 | 안건(기록 ✓) | 지금 장 크게 | 이 안건 기록 — 「기록하고 다음」(Enter) |
| `v2s-import.html` 가져오기 | 입구(메모·메일·파일) + 조각 | 원본(근거 노란 표시, PPT 장은 프레임) | 판정 → 다음 조각, 반영될 사실 |

도구줄 오른쪽 「B안 보기」로 같은 화면의 B안과 비교한다.

## ★ 최종 시안 (2026-10-23) — B안 틀 + C안 색·글자 `v2m-*`

화면 구성은 **B안 그대로**(왼쪽 사이드바 · 흰 카드 그룹 목록 · 조밀 · 끝내면 다음으로), 색과 글자 느낌은 **C안 스튜디오**에서 가져왔다. 색 덮개 `v2m.css` 하나를 `v2b.css` 위에 얹는다.

- 사이드바 = 네이비 `#1c2f4f`(회의 슬라이드 띠와 같은 남색), 바탕 = 연한 청회색 `#eef1f5`, 카드 = 흰 종이(라이트·다크 모두), 주 색·선택 = Figma 파랑 `#0a6cd6`(선택 행은 왼쪽 파란 막대). 편집 스튜디오의 캔버스만 어둡게.
- 제목은 남색, 섹션 머리는 스튜디오 프레임 라벨처럼 회색. (처음엔 바탕을 어두운 회색으로 했으나 「검은 색은 별로」 의견으로 바꿈)
- 대비: 바탕 위 글자 17.6:1 · 섹션 머리 6.0:1 · 사이드바 글자 10.6:1 · 주 버튼 5.0:1 · 연한 파랑 위 글자 6.1:1 — 7개 화면 자동 측정에서 4.5:1 미만 0.

### 슬라이드 레이아웃 방식

- **반고정 + 변경 가능**: 형태(상세·카드·사진·한 줄)로 초안 레이아웃 제공
- 초안 이후 개체 위치·크기·내용을 자유롭게 수정 가능
- 형태 전환 시 현재 개체 조정값 초기화 여부를 사용자에게 확인 _(미구현)_
- **뱃지 개체 분리**: 이슈 유형(이슈/문제점/공유)은 제목 텍스트와 별도 개체로 분리 — 각각 독립 선택·수정 가능

### 이슈 후보 패널 _(1차 보완, 인터뷰 2026-11-11 확정)_

- 지금은 `ISSUES` 고정 데이터로 슬라이드가 자동 생성될 뿐, 사용자가 다룰 이슈를 직접 고르거나 뺄 방법이 없다
- 썸네일 목록 쪽(또는 별도 패널)에 원장 이슈를 체크 → 슬라이드로 추가/제외하는 「후보」 패널을 둔다 — `v2b-studio`/`v2m-studio`에 있던 "후보" 개념을 v2e에도 이식
- 실제 이슈 데이터와의 양방향 동기화(사실 반영·변경 알림)는 기존 명세대로 2차(서버 구현 필요) 범위 유지

### 편집 인터랙션 — 개체

- **클릭** → 파란 선택 테두리 + 핸들(모서리·중간 8개)
- **텍스트 더블클릭** → 인라인 커서 활성화, 직접 입력
- **개체 경계(엣지) hover** → 리사이즈 커서 자동 변경 (↔ ↕ ↗ 방향)
- **핸들 드래그 또는 경계 드래그** → 크기 조절 (실시간 반영) / _(비율 고정 옵션 미구현)_
- **개체 드래그** → 위치 이동 / _(스냅 가이드 선 미구현)_
- **Shift + 화살표 키** → 10px 단위 이동
- **화살표 키** → 1px 단위 이동
- **Delete 키** → 개체 삭제 (Ctrl+Z 로 복원 가능)
- **Escape** → 선택 해제 / 텍스트 편집 종료
- **슬라이드 빈 곳 클릭** → 선택 해제

### 레이어 순서 (z-order)

- 오른쪽 패널 「▲ 앞으로 / ▼ 뒤로」 버튼으로 개체 적층 순서 변경
- 사진 위에 도형을 올릴 때: 도형 추가 후 「▲ 앞으로」로 이미지 레이어 위로 이동
- 머리띠·바닥띠(잠금 개체) 뒤로는 순서 변경 불가

### 이미지 · 사진 편집

- **삽입 방법**: 로컬 파일 업로드(더블클릭 또는 속성 패널) / _(URL 입력 미구현)_ / _(이슈 첨부 사진 가져오기 미구현)_ / _(드래그&드롭 미구현)_
- **기본 조정**: 위치·크기 (핸들/경계 드래그) · 밝기·대비 필터 / _(자르기(crop) 미구현)_

#### 사진 위 마커(도형) — 도형 추가로 통합

별도의 마커 도구 없이, **사진 위에 도형(원·화살표·사각형)을 올려 주석**을 단다.

|------|------|------|

| 범위 강조 | 반투명 사각형 | 「점검 구간」 색 블록 |

> **결정**: 별도의 마커 전용 도구(펜·형광펜)는 1차 범위에서 제외.

### 저장·이력

- **자동 저장**: 편집 후 약 1~2초 대기 → 자동 저장 표시 (시안 단계는 메모리 상태만 반영한 가짜 표시 — 정적 목업이라 브라우저가 임의 폴더에 자동으로 쓸 수 없음)
- **실제 저장(2차)**: 구현 단계에서 생성물을 `output/` 폴더(또는 서버)에 저장. 목업 단계에서는 저장 로직을 추가 구현하지 않는다 _(인터뷰 2026-11-11 확정 — 알려진 버그 #4 참고)_
- **되돌리기**: Ctrl+Z (편집 단계별, 최대 50단계). 구조 변경뿐 아니라 속성 패널 입력(글씨 크기·색·밝기·대비·채움색·투명도·위치·크기 직접 입력 등)도 히스토리에 포함 _(1차 보완 — 알려진 버그 #1·#2 수정 대상, 인터뷰 2026-11-11 확정)_
- **다시 실행**: Ctrl+Y / Ctrl+Shift+Z

### 제출 _(1차 보완, 인터뷰 2026-11-11 확정)_

- 머리 도구줄에 「제출」 버튼 추가 — 누르면 슬라이드 데이터에 제출 상태(제출됨/초안)만 기록

- 회의 진행 화면과의 연동, 제출 취소/재제출 등 운영 흐름은 2차(서버 구현 단계)로 미룸

| 4 | **"저장됨" 표시가 실제 저장을 의미하지 않음** — 메모리 상태일 뿐 localStorage·서버 저장이 전혀 없어 새로고침이나 갈래(부서/공유회/팀장) 탭 전환만 해도 작업이 전부 사라짐 | 자동 저장 표시 로직 | 테스터가 "저장됨" 뱃지를 보고 안심했다가 작업을 잃을 위험 — **의도적으로 2차로 분리**: 실제 저장은 구현 단계에서 `output/` 폴더(또는 서버)에 저장(인터뷰 2026-11-11), 목업 단계는 가짜 표시 유지 |
