# UI 패턴 사전 (모든 프로젝트 공통)

> 목적: 같은 기능도 여러 UI 패턴으로 만들 수 있다. 패턴 이름으로 후보를 여러 개 만들어 비교하고, 고른 결과를 프로젝트 디자인 규칙의 "컴포넌트 토큰"(meeting_v는 docs/디자인_규칙.md)으로 고정한다.
> AI에게는 "날짜 고르게 해줘"가 아니라 "데이트 피커 + 오늘·어제 빠른 선택 칩으로"처럼 이름으로 말한다. 이름 없이 말하면 매번 가장 흔한 화면이 나온다.
> 참고: 인스타그램 @uxwoodytips의 UI 이름 정리 게시물(2026-10~11)에서 아이디어를 얻어 업무용 Streamlit 앱 기준으로 다시 정리했다.
> 표의 Streamlit 칸: 기본 제공 = 내장 위젯으로 가능 / 대체 = 비슷한 내장 위젯으로 / 직접 = CSS·컴포넌트 추가 구현 필요

---

## 1. 비교 → 확정 절차

1. **기능 정의**: 누가, 얼마나 자주, 얼마나 정확한 값이 필요한가 (예: 주 1회, 주 단위면 충분)
2. **후보 3개 이상**: 아래 표에서 이름으로 후보를 고른다. AI에게 "같은 기능을 A, B, C 패턴으로 각각 만들어 비교 화면으로 보여줘"라고 요청한다.
3. **비교 기준** (기능마다 표로 채운다)

   | 기준 | 보는 것 |
   |---|---|
   | 클릭 수 | 가장 흔한 값까지 몇 번 만에 가는가 |
   | 오류 가능성 | 잘못된 값을 넣을 여지 (자유 입력 vs 선택) |
   | 화면 공간 | 상시 노출 면적, 주변 요소와의 균형 |
   | 익숙함 | 사용자가 설명 없이 쓰는가 |
   | 일관성 | 다른 화면의 같은 기능과 같은 패턴인가 |
   | 구현 비용 | Streamlit 기본 제공 / 대체 / 직접 |

4. **확정**: 고른 패턴을 프로젝트 디자인 규칙의 "컴포넌트 토큰"(meeting_v는 docs/디자인_규칙.md) 표에 `기능 → 패턴` 으로 적고, 이유와 버린 안은 디자인 규칙 문서의 변경 이력에 남긴다.
5. **재사용**: 이후 같은 기능은 토큰을 그대로 쓴다. 바꿀 때는 다시 1~4를 거친다.

## 2. 날짜·시간 선택

| 패턴 | 언제 쓰나 | 피할 때 | Streamlit |
|---|---|---|---|
| 캘린더 (데이트 피커) | 날짜를 달력에서 보고 골라야 할 때, 요일이 의미 있을 때 | 몇 년 전 날짜(생년월일), 자주 같은 값을 고를 때 | 기본 제공 `st.date_input` |
| 직접 입력 (형식 고정 입력칸) | 이미 아는 날짜를 빠르게 칠 때, 키보드 위주 사용자 | 사용자가 날짜를 모를 때 | 대체 `st.text_input` + 형식 검사 |
| 빠른 선택 칩 | 대부분 "오늘·어제·이번 주"처럼 정해진 값일 때 | 임의 날짜가 자주 필요할 때 (칩 + 캘린더 병행) | 기본 제공 `st.pills`, `st.segmented_control` |
| 범위 선택 (시작~종료) | 기간 필터, 체크인·체크아웃처럼 두 날짜가 한 쌍일 때 | 단일 날짜 | 기본 제공 `st.date_input`에 (시작, 종료) |
| 월 선택 | 월간 보고, 월 단위 집계 | 일 단위가 필요할 때 | 대체 `st.selectbox`(연-월 목록) |
| 주 선택 | 주간 회의·주간 보고 | 일 단위가 필요할 때 | 대체 `st.selectbox`(주차 목록) + 이번 주·지난 주 칩 |
| 휠 피커 | 모바일 앱에서 시·분 선택 | 데스크톱 업무 화면 | 직접 (업무 앱에서는 쓰지 않음) |
| 시간 슬롯 | 예약처럼 정해진 칸 중 하나를 고를 때 | 자유로운 시각 | 대체 `st.pills` 또는 버튼 그리드 |
| 시간 입력 | 임의 시각 | 정해진 칸이 있을 때 | 기본 제공 `st.time_input` |

## 3. 켜고 끄기·고르기

| 패턴 | 언제 쓰나 | 피할 때 | Streamlit |
|---|---|---|---|
| 토글 | 누르자마자 바로 적용되는 켜기/끄기 | 저장 버튼을 눌러야 반영될 때 | 기본 제공 `st.toggle` |
| 체크박스 | 저장을 눌러야 반영되는 선택, 여러 개 동시 선택 | 즉시 적용 설정 | 기본 제공 `st.checkbox` |
| 라디오 | 2~5개 중 하나, 모든 선택지를 보여줘야 할 때 | 선택지 6개 이상 | 기본 제공 `st.radio` |
| 세그먼트 컨트롤 | 2~4개 중 하나로 보기 전환 (표/카드, 주/월) | 선택지가 길거나 많을 때 | 기본 제공 `st.segmented_control` |
| 필터 칩 | 여러 조건을 켜고 끄는 필터 | 조건이 10개 이상 | 기본 제공 `st.pills` (다중 선택) |
| 셀렉트 (선택 상자) | 6개 이상 중 하나, 고른 값이 남아야 할 때 | 2~3개 (라디오가 빠름) | 기본 제공 `st.selectbox` |
| 검색형 셀렉트 (콤보박스) | 항목이 매우 많을 때 (호선, 사람) | 항목이 적을 때 | 기본 제공 `st.selectbox` (입력 검색 지원) |
| 다중 셀렉트 | 많은 항목 중 여러 개 | 3~4개 중 여러 개 (체크박스·칩) | 기본 제공 `st.multiselect` |
| 드롭다운 메뉴 | 고르는 즉시 동작 실행 (내보내기, 삭제 등 메뉴) | 값을 저장해야 할 때 (셀렉트) | 대체 `st.popover` + 버튼 |
| 슬라이더 | 대략적인 범위·수준 | 정확한 숫자 | 기본 제공 `st.slider`, `st.select_slider` |

## 4. 알림·피드백·확인

| 패턴 | 언제 쓰나 | 피할 때 | Streamlit |
|---|---|---|---|
| 토스트 | 보기만 하면 되는 결과 알림 (저장됨) | 사용자가 대응해야 할 때 | 기본 제공 `st.toast` |
| 스낵바 (되돌리기 포함) | 결과 알림 + 버튼 하나 (되돌리기) | 반드시 답해야 할 때 | 직접 (토스트 + 되돌리기 버튼 영역) |
| 배너 | 화면 전체에 해당하는 상태 (마감 임박, 점검 중) | 한 항목에만 해당할 때 | 기본 제공 `st.info`·`st.warning` (화면 상단) |
| 인라인 메시지 / 인라인 에러 | 특정 입력칸·항목 옆에서 바로 | 화면 전체 상태 | 대체 입력칸 아래 `st.caption` 또는 `st.error` |
| 모달 (다이얼로그) | 꼭 멈추고 답해야 할 때 (종결, 삭제, 반려 사유 입력) | 단순 알림 | 기본 제공 `@st.dialog` |
| 바텀시트 | 모바일에서 아래에서 올라오는 선택·확인 | 데스크톱 업무 화면 (모달로 대체) | 직접 (업무 앱에서는 모달 사용) |
| 팝오버 | 버튼 옆에 작게 여는 보조 설정·필터 | 중요한 확인 | 기본 제공 `st.popover` |
| 상태 배지 | 항목의 현재 상태 표시 | 행동 유도 | 직접 (디자인 규칙의 상태 배지 규칙) |

## 5. 로딩·진행

| 패턴 | 언제 쓰나 | 피할 때 | Streamlit |
|---|---|---|---|
| 스피너 | 짧은 대기 (2초 내외) | 긴 작업 | 기본 제공 `st.spinner` |
| 스켈레톤 | 목록·카드가 채워질 자리를 미리 보여줄 때 | 매우 짧은 대기 | 직접 (자리 표시 CSS) |
| 진행 바 | 진행률을 아는 긴 작업 (일괄 처리) | 진행률을 모를 때 | 기본 제공 `st.progress` |
| 단계 상태 | 여러 단계 작업 (불러오기 → 변환 → 저장) | 단일 단계 | 기본 제공 `st.status` |

## 6. 정보 보여주기

| 패턴 | 언제 쓰나 | 피할 때 | Streamlit |
|---|---|---|---|
| 표 | 같은 항목을 여러 열로 비교·정렬 | 항목마다 내용이 길고 제각각 | 기본 제공 `st.dataframe` |
| 편집 가능한 표 | 여러 행을 한 번에 고칠 때 | 한 건씩 신중히 입력할 때 (폼) | 기본 제공 `st.data_editor` |
| 리스트 (줄) | 훑어보며 하나를 고를 때 | 열 비교가 필요할 때 | 대체 컨테이너 반복 |
| 카드 (칸) | 항목마다 요약·상태가 한눈에 보여야 할 때 | 항목이 수십 개 이상 (표가 낫다) | 대체 `st.columns` + 컨테이너 |
| KPI 메트릭 | 핵심 숫자 1~4개 | 숫자가 많을 때 | 기본 제공 `st.metric` |
| 타임라인 | 시간 순서의 이력 (상태 변경) | 순서가 의미 없을 때 | 직접 |
| 접기 (아코디언) | 가끔 보는 상세·옵션 | 핵심 정보 | 기본 제공 `st.expander` |
| 빈 상태 | 데이터가 없을 때 무엇을 하면 되는지 안내 | 데이터가 있을 때 | 직접 (문구 + 행동 버튼) |

## 7. 화면 배치

| 패턴 | 언제 쓰나 | Streamlit |
|---|---|---|
| 사이드바 레이아웃 | 메뉴·공통 필터가 왼쪽에 고정 | 기본 제공 `st.sidebar` |
| 대시보드 | 핵심 숫자 → 추이 → 상세 순 | 대체 `st.columns` |
| 목록 + 상세 (마스터-디테일) | 왼쪽 목록에서 고르면 오른쪽에 상세 | 대체 `st.columns` + 표 행 선택 |
| 탭 | 같은 대상의 다른 관점 (요약/이력/첨부) | 기본 제공 `st.tabs` |
| 카드 그리드 | 비슷한 항목 여러 개를 칸으로 | 대체 `st.columns` |
| 스플릿 | 입력과 미리보기를 나란히 | 대체 `st.columns(2)` |
| 단계 진행 (스테퍼) | 순서가 정해진 입력 (1. 정보 → 2. 확인 → 3. 제출) | 직접 (상단 단계 표시 + 단계별 화면) |
| 히어로 · 벤토 그리드 · 매거진 · 풀블리드 | 소개·홍보 페이지 | 업무 앱에서는 쓰지 않음 |

## 8. 이동·실행

| 구분 | 차이 |
|---|---|
| 버튼 vs 링크 | 버튼은 실행(저장, 제출), 링크는 이동(다른 화면 열기) |
| 셀렉트 vs 드롭다운 메뉴 | 셀렉트는 고른 값이 남음, 드롭다운 메뉴는 고르는 즉시 실행 |
| 라벨 vs 플레이스홀더 | 라벨은 항상 남는 이름, 플레이스홀더는 입력하면 사라지는 예시. 이름은 반드시 라벨로 |
| 햄버거 vs 케밥 | 줄 세 개는 전체 메뉴, 점 세 개는 그 항목의 추가 동작 |
| 주요 버튼 vs 아이콘 버튼 | 화면당 주요 버튼 1개, 보조 동작은 아이콘 버튼 + 툴팁 |

## 9. 모든 컴포넌트가 갖춰야 할 상태

기본 / 호버 / 눌림 / 포커스 / 비활성 / 로딩 / 성공 / 오류 / 선택됨.
AI에게 컴포넌트를 시킬 때는 "기본·호버·눌림·포커스·비활성·로딩·성공·오류 상태를 모두 만들어줘"라고 말한다. 상태가 빠지면 눌러도 반응이 없는 것처럼 보인다.

## 10. 화면 전환·움직임 (업무 앱은 최소한으로)

| 패턴 | 의미 | 업무 앱 |
|---|---|---|
| 푸시 (옆에서 밀려 들어옴) | 다음 단계로 이동 | 쓰지 않음 (Streamlit 페이지 전환 그대로) |
| 모달 등장 | 현재 화면 위에 확인 | 모달에만 |
| 카운트 업 (숫자가 올라감) | KPI 강조 | 쓰지 않음 (숫자를 정확히 읽는 게 우선) |
| 타이핑·스크램블·블러 인 | 텍스트 연출 | 쓰지 않음 |

## 11. AI에게 말하는 법 (예시)

| 막연한 요청 | 이름으로 말하기 |
|---|---|
| 날짜 고르게 해줘 | 주 선택 셀렉트 + 이번 주·지난 주 빠른 선택 칩으로 |
| 저장됐다고 알려줘 | 토스트로 짧게 |
| 확인 창 띄워줘 | 모달로, 확인·취소 버튼, 확인은 위험 색 |
| 로딩 넣어줘 | 목록 자리에 스켈레톤으로 |
| 틀리면 알려줘 | 입력칸 바로 아래 인라인 에러로 |
| 깔끔하게 배치해줘 | 사이드바 레이아웃, 위는 KPI 메트릭 3개, 아래는 표 |
| 같은 기능 여러 안 보여줘 | 날짜 입력을 캘린더 / 빠른 선택 칩 + 캘린더 / 주 선택 셀렉트 3안으로 만들어 1장의 비교 기준표로 비교해줘 |
